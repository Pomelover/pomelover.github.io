1.7 坐标系统

学习笔记系列，教程：Joey de Vries《LearnOpenGL》，中文版地址 learnopengl-cn.github.io。

　　把坐标变换为标准化设备坐标（Normalized Device Coordinate, NDC）、再转化为屏幕坐标的过程通常是分步进行的，类似于流水线。在流水线中，物体的顶点在最终转化为屏幕坐标之前，还会被变换到多个坐标系统（Coordinate System）。

　　将物体的坐标变换到几个过渡坐标系（Intermediate Coordinate System）的好处在于：在每一个特定的坐标系统中，总有一些操作或运算会更加方便、更容易完成——这一点很快就体现出来。

　　其中有 5 个不同的坐标系统值得关注：

  1. 局部空间（Local Space），也称为物体空间（Object Space）
  2. 世界空间（World Space）
  3. 观察空间（View Space），也称为视觉空间（Eye Space）
  4. 裁剪空间（Clip Space）
  5. 屏幕空间（Screen Space）

Tip：这五个空间其实各自对应一类「最顺手」的操作：在局部空间里改模型形状最直观（顶点坐标就是相对于物体原点的）；在世界空间里摆放物体、处理物体之间的相对关系最自然；在观察空间里做与视角相关的判断（例如视锥剔除、沿视线方向的光照）最方便；裁剪空间负责把可见范围统一压进 的立方体，好让 GPU 用同一套规则做裁剪；而屏幕空间才是最后落到像素上、能直接和鼠标坐标挂钩的那一层。记住这条对应关系，后面每讲一个矩阵都能立刻回答「它为什么必须在这一步做」。

1.7.1 概述

　　为了把坐标从一个坐标系变换到另一个坐标系，需要用到几个变换矩阵，其中最重要的是模型（Model）、观察（View）、投影（Projection）三个矩阵。

　　顶点坐标起始于局部空间（Local Space），在这里它被称为局部坐标（Local Coordinate）；此后它会依次变为世界坐标（World Coordinate）、观察坐标（View Coordinate）、裁剪坐标（Clip Coordinate），最后以屏幕坐标（Screen Coordinate）的形式结束。

Tip：这三个矩阵恰好把上面前四个坐标系串了起来：模型矩阵负责局部空间 → 世界空间，观察矩阵负责世界空间 → 观察空间，投影矩阵负责观察空间 → 裁剪空间（图中通常写作 MVP）。要注意它们并非全部定义在顶点着色器里——模型矩阵与观察矩阵的乘积常被合并成一个 view * model，在物体数量多时只需每帧为每个物体更新一次，而光源或视图相关的部分（如相机位置、投影参数）则作为 uniform 统一传入，不必逐顶点重复计算。

　　每个空间的具体作用如下：

  1. 局部坐标是对象相对于局部原点的坐标，也是物体起始的坐标。
  2. 下一步是将局部坐标变换为世界空间坐标，世界空间坐标处于一个更大的空间范围。这些坐标相对于世界的全局原点，它们会和其它物体一起相对于世界的原点进行摆放。
  3. 接下来将世界坐标变换为观察空间坐标，使得每个坐标都是从摄像机或者说观察者的角度进行观察的。
  4. 坐标到达观察空间之后，需要将其投影到裁剪坐标。裁剪坐标会被处理至 到 的范围内，并判断哪些顶点将会出现在屏幕上。
  5. 最后，将裁剪坐标变换为屏幕坐标，这一步使用一个叫做视口变换（Viewport Transform）的过程。视口变换将位于 到 范围的坐标变换到由 glViewport 函数所定义的坐标范围内，最后变换出来的坐标将会送到光栅器，将其转化为片段。

Tip：第 5 步有两个容易混淆的点。一是视口变换不需要自己写着色器，它属于固定管线，由 glViewport 的设置决定，所以顶点着色器的输出停在裁剪空间就够了；二是这里的「屏幕坐标」与窗口像素之间还隔着一步——光栅器会把图元覆盖到的像素逐个生成片段（Fragment），片段的屏幕位置才是最终的像素坐标，而 gl_FragCoord 正是由这一步产生的，这也是 1.3 中片元着色器的输入来源。

1.7.2 局部空间

　　局部空间是指物体所在的坐标空间，即对象最开始所在的地方。

1.7.3 世界空间

　　世界空间坐标是指顶点相对于（游戏）世界的坐标。物体的坐标将会从局部变换到世界空间，而该变换是由模型矩阵（Model Matrix）实现的。

　　模型矩阵是一种变换矩阵，它能通过对物体进行位移、缩放、旋转，把它置于本应该在的位置或朝向。

Tip：模型矩阵通常记作 ，即先缩放、再旋转、最后位移（回忆 1.6 中「从右向左读」的乘法顺序）。因为每个物体都各有一个模型矩阵，所以可以只维护一份局部顶点数据，再为每个物体传入不同的 model uniform，就能在场景里摆出成百上千个位置与朝向各异的副本；这也是把「形状」与「摆放」分开之后最直接的收益。

1.7.4 观察空间

　　观察空间经常被称为 OpenGL 的摄像机（Camera），所以有时也被称为摄像机空间（Camera Space）或视觉空间（Eye Space）。观察空间是将世界空间坐标转化为用户视野前方的坐标而产生的结果，因此观察空间就是从摄像机的视角所观察到的空间。

　　这一步通常由一系列的位移和旋转组合而成：平移、旋转整个场景，从而使得特定的对象被变换到摄像机的前方。这些组合在一起的变换通常存储在一个观察矩阵（View Matrix）里，它被用来把世界坐标变换到观察空间。

Tip：上面这段话的「反直觉」之处在于「平移的是场景而不是相机」。可以这样理解：相机原本站在世界原点上、朝着 方向看；现在要把它挪到世界里的某个位置 、并转向某个朝向，等价于反过来把整个世界平移 、再按相机朝向的反方向旋转，让相机在变换之后仍然停在原点看向 。观察矩阵因此就是相机自身世界变换的逆矩阵，构造它需要的信息只有三样：相机位置、看向的目标点、以及上方向（这正是 glm::lookAt 的三个参数）。变换后，凡是落在相机前方的物体坐标为负 ，落在一旁或身后的则被排除，为下一步投影做好了准备。

1.7.5 裁剪空间

　　在一个顶点着色器运行的最后，OpenGL 期望所有的坐标都能落在一个特定的范围内，且任何在这个范围之外的点都应该被裁剪（Clipped）掉。被裁剪掉的坐标会被忽略，所以剩下的坐标就将变为屏幕上可见的片段。

　　为了将顶点坐标从观察变换到裁剪空间，需要定义一个投影矩阵（Projection Matrix），它指定了一个范围的坐标，比如在每个维度上的 到 。投影矩阵接着会将在这个指定范围内的坐标变换为标准化设备坐标的范围 。所有在范围外的坐标不会被映射到 到 之间，所以会被裁剪掉。

　　由投影矩阵创建的观察箱（Viewing Box）被称为平截头体（Frustum），每个出现在平截头体范围内的坐标都会最终出现在用户的屏幕上。将特定范围内的坐标转化到标准化设备坐标系的过程（而且它很容易被映射到 2D 观察空间坐标）被称为投影（Projection）——因为使用投影矩阵能将 3D 坐标投影（Project）到很容易映射到 2D 的标准化设备坐标系中。

Tip：Frustum 的直译是「平截头体」，也就是金字塔被削掉顶端剩下的那一段——这正是投影矩阵所定义的那块可见区域：靠近相机的一端是窄的（近平面），远端是宽的（远平面）。记住这个形状，后面区分正射投影（长方体）与透视投影（四棱台）时就不必死记名字。

　　一旦所有顶点被变换到裁剪空间，最终的操作——透视除法（Perspective Division）将会执行。在这个过程中，位置向量的 、、 分量会被分别除以它的齐次 分量；透视除法是把 4D 裁剪空间坐标变换为 3D 标准化设备坐标的过程。这一步会在每一个顶点着色器运行的最后被自动执行。

　　在这一阶段之后，最终的坐标将会被映射到屏幕空间中（使用 glViewport 中的设定），并被变换成片段。

Tip：透视除法正是 1.6 里那句「 分量另有其他用途」的兑现——它为位移腾出了位置，又在这里成为实现透视的手段。记忆上可以拆成两半：**投影矩阵负责改写 ，透视除法负责除以 **。正射投影下 始终为 ，除以它等于什么都没做，所以远处的物体不会变小；透视投影下 随距离增大，除以它之后远处的顶点就被压小，透视感由此而来。

　　将观察坐标变换为裁剪坐标的投影矩阵可以为两种不同的形式，每种形式都定义了不同的平截头体。可以选择创建一个正射投影矩阵（Orthographic Projection Matrix）或一个透视投影矩阵（Perspective Projection Matrix）。

正射投影

　　正射投影矩阵定义了一个类似立方体的平截头箱，它定义了一个裁剪空间，在这个空间之外的顶点都会被裁剪掉。创建一个正射投影矩阵需要指定可见平截头体的宽、高和长度。在使用正射投影矩阵变换至裁剪空间之后，处于这个平截头体内的所有坐标将不会被裁剪掉。

　　如果曾经体验过实际生活带来的景象，就会注意到离得越远的东西看起来越小。这个奇怪的效果称之为透视（Perspective）。由于透视，两条平行的线在很远的地方看起来会相交。这正是透视投影想要模仿的效果，它是使用透视投影矩阵来完成的。

　　这正是观察矩阵所做的：以相反于摄像机移动的方向移动整个场景。因为想要往后移动，并且 OpenGL 是一个右手坐标系（Right-handed System），所以需要沿着 轴的正方向移动——通过将场景沿着 轴负方向平移来实现，它会给出一种在往后移动的感觉。

右手坐标系（Right-handed System）

　　按照惯例，OpenGL 是一个右手坐标系。简单来说，就是正 轴在右手边，正 轴朝上，而正 轴是朝向后方的。想象屏幕处于三个轴的中心，则正 轴穿过屏幕朝向观察者。坐标系画起来如下：

　　为了理解为什么被称为右手坐标系，按如下步骤做：

  • 沿着正 轴方向伸出右臂，手指着上方。
  • 大拇指指向右方。
  • 食指指向上方。
  • 中指向下弯曲 90 度。

　　如果动作正确，那么大拇指指向正 轴方向，食指指向正 轴方向，中指指向正 轴方向。如果用左臂来做这些动作，会发现 轴的方向是相反的——这个叫做左手坐标系，它被 DirectX 广泛地使用。注意在标准化设备坐标系中 OpenGL 实际上使用的是左手坐标系（投影矩阵交换了左右手）。

Tip：这条手势规则也解释了 1.7.4 里「相机默认朝 看」——在右手系中 指向观察者、 越小越远，所以「把场景往后推」就是沿 平移场景。

Z 缓冲

　　OpenGL 把它的所有深度信息存储在一个 Z 缓冲（Z-buffer）中，也被称为深度缓冲（Depth Buffer）。GLFW 会自动生成这样一个缓冲（就像它也有一个颜色缓冲来存储输出图像的颜色）。深度值存储在每个片段里面（作为片段的 值），当片段想要输出它的颜色时，OpenGL 会将它的深度值和 Z 缓冲进行比较：如果当前的片段在其它片段之后，它将会被丢弃，否则将会覆盖。这个过程称为深度测试（Depth Testing），它是由 OpenGL 自动完成的。

小结

　　本章把顶点的坐标变换拆成流水线上的五个空间，每个空间用一个变换矩阵连接，最后用三个矩阵（模型、观察、投影）把物体从局部空间一路送到屏幕上。

  • 五个坐标系统：局部空间 → 世界空间 → 观察空间 → 裁剪空间 → 屏幕空间。分步变换的意义在于每个空间里都有各自最顺手的操作。
  • 模型矩阵：把局部坐标变换到世界空间，通过对物体位移、缩放、旋转把它摆到该在的位置与朝向。
  • 观察矩阵：把世界坐标变换到观察空间（摄像机空间）。「平移的是场景而不是相机」——它是相机自身世界变换的逆矩阵。
  • 投影矩阵：把观察坐标变换到裁剪空间，并用 分量编码距离；随后透视除法（各分量除以 ）把它们变为标准化设备坐标，这一步由固定管线自动完成。
  • 正射投影与透视投影是投影矩阵的两种形式：前者 保持 、没有透视效果，主要用于 2D 与建筑/工程类程序；后者模仿近大远小，用 glm::perspective 构造，其 near 设太大或 far 设太远都会出问题（近处被裁掉、远处 z-fighting）。
  • 组合：，乘法要从右往左读，最终结果赋给 gl_Position。
  • 实践：把三个矩阵作为 uniform 传入顶点着色器，即可把 2D 平面拓展成随时间旋转的立方体；多个物体只需要各自的模型矩阵；Z 缓冲与 glEnable(GL_DEPTH_TEST) 负责处理面片的前后遮挡。
