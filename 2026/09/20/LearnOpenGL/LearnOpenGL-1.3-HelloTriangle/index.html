1.3 你好，三角形

学习笔记系列，教程：Joey de Vries《LearnOpenGL》，中文版地址 learnopengl-cn.github.io。

　　在进入本节之前，建议先把下面三个词记下来——正文中会交替使用英文缩写与中文全称，二者指代的始终是同一个东西，不要当成不同的概念：

缩写 英文全称 中文全称
VAO Vertex Array Object 顶点数组对象
VBO Vertex Buffer Object 顶点缓冲对象
EBO / IBO Element Buffer Object / Index Buffer Object 元素缓冲对象 / 索引缓冲对象

　　原文是分词书写的英文，一个全称一眼就能看清边界；译成中文之后没有空格分隔，全称夹在句子里不太容易注意到。因此阅读时更要留心：凡出现中文全称处，指的就是上表中对应的缩写。

Tip：EBO 与 IBO 是同一个对象的两种叫法，教程的正文和代码注释里会混用，不影响实际 API——它们在 OpenGL 中对应的绑定目标都是 GL_ELEMENT_ARRAY_BUFFER。

　　在 OpenGL 中，任何事物都处在 3D 空间中，而屏幕和窗口却是 2D 像素数组。这导致 OpenGL 的大部分工作，都是关于把 3D 坐标转变为适应屏幕的 2D 像素。

　　3D 坐标转为 2D 坐标的处理过程，由 OpenGL 的图形渲染管线（Graphics Pipeline）管理。Pipeline 大多译为「管线」，实际上指的是这样一个过程：一堆原始图形数据途经一条输送管道，期间经过各种变化处理，最终出现在屏幕上。图形渲染管线可以被划分为两个主要部分：

  1. 第一部分把 3D 坐标转换为 2D 坐标；
  2. 第二部分把 2D 坐标转变为实际的有颜色的像素。

　　本节会简单地讨论一下图形渲染管线，以及如何利用它创建一些漂亮的像素。

　　图形渲染管线接受一组 3D 坐标，然后把它们转变为屏幕上的有色 2D 像素输出。图形渲染管线可以被划分为几个阶段，每个阶段都会把前一个阶段的输出作为自己的输入。所有这些阶段都是高度专门化的（各自都有一个特定的函数），并且很容易并行执行。

　　正是由于这种并行执行的特性，当今大多数显卡都有成千上万的小处理核心，它们在 GPU 上为每一个管线阶段运行各自的小程序，从而在图形渲染管线中快速处理数据。这些小程序叫做着色器（Shader）。

Tip：着色器是运行在 GPU 上的程序，用类 C 的 GLSL 编写，由驱动在运行时编译、链接——所以写错着色器不会在 C++ 编译期报错，只会在运行时报错，返回值同样是 GLuint 形式的句柄。另外并非每个阶段都可编程：管线中可编程的只是其中若干阶段，本节用到的顶点着色器与片段着色器是必选的两个，几何着色器等阶段则是可选的。

　　数据自左向右流动：顶点数据（VERTEX DATA[]）依次经过顶点着色器（Vertex Shader）、几何着色器（Geometry Shader）、形状（图元）装配（Shape Assembly）、光栅化（Rasterization）、片段着色器（Fragment Shader），最后由测试与混合（Tests and Blending）阶段写出屏幕上的像素。

　　需要注意，图中的蓝色部分代表的是可以注入自定义着色器的阶段。

Tip：与蓝色阶段相对，其余阶段（几何着色器之后的图元装配、光栅化、测试与混合）属于固定功能阶段，不能写代码替换，只能通过少量状态开关去影响它——比如 glPolygonMode 决定图元以点、线还是面填充，深度测试与混合模式则各自有对应的开关。理解「哪些阶段能写代码、哪些只能配置状态」，是判断一个渲染效果该从哪里下手的前提。

　　下面先对各阶段做一个概括性的解释，从中可以看出图形渲染管线的工作方式。

　　首先，以数组的形式传递 3 个 3D 坐标作为图形渲染管线的输入，用来表示一个三角形，这个数组叫做顶点数据（Vertex Data）；顶点数据是一系列顶点的集合。一个顶点（Vertex）是一个 3D 坐标的数据的集合，而这样一个顶点的数据是用顶点属性（Vertex Attribute）表示的——它可以包含任何想用的数据，但为简单起见，这里先假定每个顶点只由一个 3D 位置和一些颜色值组成。

Tip：为了让 OpenGL 知道坐标和颜色值构成的到底是什么，还需要指定这些数据所表示的渲染类型——渲染成一系列的点？一系列的三角形？还是一条长长的线？这类提示叫做图元（Primitive），任何一个绘制指令的调用都会把图元传递给 OpenGL，其中几个是 GL_POINTS、GL_TRIANGLES、GL_LINE_STRIP。

　　图形渲染管线的第一个部分是顶点着色器（Vertex Shader），它把一个单独的顶点作为输入。顶点着色器主要的目的是把 3D 坐标转为另一种 3D 坐标，同时顶点着色器允许对顶点属性进行一些基本处理。

Tip：这里的「3D 坐标转为另一种 3D 坐标」就是坐标变换的入口——本节只做最朴素的传递，而变换（Transformations）与坐标系统（Coordinate Systems）两节会依次补上模型矩阵、视图矩阵与投影矩阵，把顶点从局部空间一路送到裁剪空间。也就是说，顶点着色器是整条管线里唯一对顶点位置做数学变换的地方，光照、骨骼动画等逐顶点计算也都发生在这里。

　　顶点着色器阶段的输出可以选择性地传递给几何着色器（Geometry Shader）。几何着色器将一组顶点作为输入，这些顶点形成图元，并且能够通过发出新的顶点来形成新的（或其他）图元，从而生成其他形状。

Tip：几何着色器是可选的可编程阶段，本节并不使用它，管线会直接跳过。它作用在图元粒度上——一次拿到的不是一个顶点，而是一整个图元的所有顶点，因此可以增删顶点、改变输出的图元类型，乃至凭空生成几何；顶点着色器只能逐顶点「一进一出」。它需要显式声明输入图元与输出规模：

通过 EmitVertex() 与 EndPrimitive() 自行发出 0 个、1 个或多个顶点组装出新图元，也可以一个都不发（等于丢弃该图元）。典型用途是把一个点扩成面向摄像机的四边形（粒子、公告板）、细分三角形、程序化长草与毛发、调试时画法线、单遍渲染立方体贴图。它与图元装配的分工如下：

图元装配 几何着色器
性质 固定功能，不可编程 可编程，自己写 GLSL
粒度 顶点流 → 图元 图元 → 顶点流
顶点数 一个不增、一个不减，只做分组 可增、可减、可生成新顶点
图元类型 由绘制调用的参数决定，自己改不了 可在着色器内改变输出类型

两者是接力关系：图元装配负责「把这些顶点按规则捆成一个图元」，几何着色器负责「拿到这个图元，随便折腾出一批新顶点」，而这些新顶点又要再被装配一次才继续往后走。需要注意，图上虽然把「形状装配」画在几何着色器之后，但几何着色器的输入同样是装配好的图元——装配在其前后各发生一次，后一次装的是它输出顶点流构成的图元。另外它需要缓存整个图元、并行度低、驱动优化普遍不佳，移动端到 GLES 3.2 才进入核心，因此实际项目中用得相当克制。

　　图元装配（Primitive Assembly）阶段将顶点着色器（或几何着色器）输出的所有顶点作为输入（如果是 GL_POINTS，那么就是一个顶点），并将所有的点装配成指定图元的形状；本节例子中是两个三角形。

Tip：这一阶段属于固定功能，装配成什么形状完全由绘制调用时给出的图元类型决定，代码里能做的只是选对图元。需要注意装配时顶点的顺序是有含义的——它决定了三角形的绕序（顺时针或逆时针），而绕序正是后面面剔除（Face Culling）判断正面的依据：一旦顶点顺序写反，三角形会被当成背面剔除掉，屏幕上直接看不到它。

　　图元装配阶段的输出会被传入光栅化阶段（Rasterization Stage），这里它会把图元映射为最终屏幕上相应的像素，生成供片段着色器（Fragment Shader）使用的片段（Fragment）。在片段着色器运行之前会执行裁切（Clipping）。裁切会丢弃超出视图以外的所有像素，用来提升执行效率。

Tip：光栅化同样是固定功能阶段。它会把顶点属性沿图元表面插值后交给片段着色器——本节若给三个顶点配不同颜色，三角形内部便呈现渐变，这正是插值的结果。要注意片段并不等于像素：片段携带位置、颜色、深度等数据，只有通过后面的深度测试、模板测试与混合之后，才可能真正写进像素；同一个像素也可能先后收到多个片段的贡献（多重采样抗锯齿时尤为明显）。裁切也发生在这一环节，它丢弃视图以外的部分，属于纯效率优化，不改变可见结果。

　　片段着色器的主要目的是计算一个像素的最终颜色，这也是所有 OpenGL 高级效果产生的地方。通常，片段着色器包含 3D 场景的数据（比如光照、阴影、光的颜色等等），这些数据可以被用来计算最终像素的颜色。

Tip：片段着色器是第二个必选的可编程阶段（与顶点着色器一起构成本节实际要写的两个着色器）。它按片段逐个运行而非按像素运行，输出的颜色还要经过后面的测试与混合才会落到像素上；写在这里的计算量也是整个管线里最大的一块——纹理采样、光照模型、阴影判断、各类后处理效果几乎都发生在这一阶段。本节为了让程序先跑起来，它只是输出一个固定的橘黄色。

　　在所有对应颜色值确定以后，最终的对象将会被传到最后一个阶段，即 Alpha 测试和混合（Blending）阶段。这个阶段检测片段对应的深度（和模板（Stencil））值（后面会讲），用它们来判断这个像素是处在其他物体的前面还是后面，决定是否应该丢弃。这个阶段也会检查 alpha 值（alpha 值定义了一个物体的透明度）并对物体进行混合（Blend）。所以，即使在片段着色器中计算出了一个像素输出的颜色，在渲染多个三角形的时候，最后的像素颜色也可能完全不同。

Tip：这个阶段本身也是固定功能的，但状态可配置：深度测试、模板测试与混合都需要显式开启——glEnable(GL_DEPTH_TEST)、glEnable(GL_STENCIL_TEST)、glEnable(GL_BLEND)，并分别由 glDepthFunc、glStencilFunc 与 glStencilOp、glBlendFunc 决定具体行为。它们在 OpenGL 中默认都是关闭的，这也是「画出来的物体没有遮挡关系」这类问题的常见原因。另外核心模式下已没有 glEnable(GL_ALPHA_TEST) 这类旧接口，所谓「alpha 测试」通常改为在片段着色器里用 discard 丢弃片段来实现。

　　可以看到，图形渲染管线非常复杂，它包含很多可配置的部分。然而对于大多数场合，只需要配置顶点和片段着色器就行了；几何着色器是可选的，通常使用它默认的着色器即可。

　　在现代 OpenGL 中，必须定义至少一个顶点着色器和一个片段着色器（因为 GPU 中没有默认的顶点/片段着色器）。

Tip：这一点与旧式 OpenGL 的差别很大——早期版本走的是固定管线，内置了默认的顶点处理与光照、纹理流程，用 glBegin/glEnd 之类的接口就能直接画图，开发者可以不写着色器。核心模式把这条退路去掉了，于是「画出第一个三角形」就必须先准备着色器源码、编译链接、再配置顶点数据，代码量看起来与结果完全不成比例；本节后半部分要铺开的一长串步骤，正源于此。

1.3.1 顶点输入

　　开始绘制图形之前，需要先给 OpenGL 输入一些顶点数据。

　　OpenGL 不是简单地把所有的 3D 坐标变换为屏幕上的 2D 像素；OpenGL 仅当 3D 坐标在 3 个轴（x、y 和 z）上 -1.0 到 1.0 的范围内时才处理它。所有在这个范围内的坐标叫做标准化设备坐标（Normalized Device Coordinates），此范围内的坐标最终显示在屏幕上（在这个范围以外的坐标则不会显示）。

Tip：标准化设备坐标（Normalized Device Coordinates, NDC）——一旦顶点坐标已经在顶点着色器中处理过，它们就应该是标准化设备坐标了：它是一段 x、y 和 z 值都在 -1.0 到 1.0 之间的小空间，任何落在范围外的坐标都会被丢弃/裁剪，不会显示在屏幕上。

通过使用由 glViewport 函数提供的数据进行视口变换（Viewport Transform），标准化设备坐标会变换为屏幕空间坐标（Screen-space Coordinates）；所得的屏幕空间坐标又会被变换为片段，输入到片段着色器中。

　　定义这样的顶点数据以后，会把它作为输入发送给图形渲染管线的第一个处理阶段：顶点着色器。它会在 GPU 上创建内存用于储存顶点数据，还要配置 OpenGL 如何解释这些内存，并且指定其如何发送给显卡。顶点着色器接着会处理在内存中指定数量的顶点。

　　通过顶点缓冲对象（Vertex Buffer Objects, VBO）管理这个内存，它会在 GPU 内存（通常被称为显存）中储存大量顶点。使用这些缓冲对象的好处是可以一次性地发送一大批数据到显卡上，而不是每个顶点发送一次。从 CPU 把数据发送到显卡相对较慢，所以只要可能都要尽量一次性发送尽可能多的数据。当数据发送至显卡的内存中后，顶点着色器几乎能立即访问顶点，这是个非常快的过程。

Tip：数据从 CPU 到 GPU 要经过总线（今天主要是 PCIe），单次传输有固定的启动开销，逐顶点调用会把这笔开销重复上千次——这就是「尽量一次发完」的由来，也是渲染里最经典的瓶颈之一。工程上的延伸做法是：静态几何只在初始化时上传一次，之后每帧只发送模型矩阵之类的少量参数；确实需要频繁改动的顶点数据（粒子、动态网格）则用缓冲映射或双缓冲来避免每帧重新分配显存。

　　第四个参数指定了希望显卡如何管理给定的数据，它有三种形式：

  • GL_STATIC_DRAW：数据不会或几乎不会改变。
  • GL_DYNAMIC_DRAW：数据会被改变很多。
  • GL_STREAM_DRAW：数据每次绘制时都会改变。

Tip：第四个参数只是一个性能提示，不改变任何语义——无论填哪一个，数据都会被复制进缓冲，绘制结果完全一样；填错的代价只是显存可能被放在不适合访问方式的位置，从而变慢。换句话说，它属于「不影响正确性、只影响性能」的那类参数，调试阶段可以先照抄 GL_STATIC_DRAW，但写引擎时值得按数据的真实更新频率来选。

　　三角形的位置数据不会改变，每次渲染调用时都保持原样，所以它的使用类型最好是 GL_STATIC_DRAW。如果一个缓冲中的数据将频繁被改变，那么使用的类型就是 GL_DYNAMIC_DRAW 或 GL_STREAM_DRAW，这样就能确保显卡把数据放在能够高速写入的内存部分。

1.3.2 顶点着色器

　　顶点着色器（Vertex Shader）是几个可编程着色器中的一个。如果打算做渲染，现代 OpenGL 要求至少设置一个顶点着色器和一个片段着色器。这里会简要介绍着色器，并配置两个非常简单的着色器来绘制第一个三角形。

1.3.4 片段着色器

　　片段着色器（Fragment Shader）是第二个也是最后一个打算创建的、用于渲染三角形的着色器。片段着色器所做的是计算像素最后的颜色输出。

Tip：FragColor 这个名字是自行取的，和顶点着色器里 gl_Position 那样的内置变量不同——片段着色器的输出变量由开发者声明，核心模式下至少要写出一个 out 变量，否则着色器程序链接时会报错。它的位置默认按声明顺序分配，也可以像顶点属性那样用 layout (location = 0) out vec4 FragColor; 显式指定。

着色器程序

　　着色器程序对象（Shader Program Object）是多个着色器合并之后并最终链接完成的版本。如果要使用刚才编译的着色器，必须把它们链接（Link）为一个着色器程序对象，然后在渲染对象的时候激活这个着色器程序。

　　当链接着色器至一个程序的时候，它会把每个着色器的输出链接到下个着色器的输入。当输出和输入不匹配的时候，会得到一个链接错误。

Tip：所谓「不匹配」通常指顶点着色器里的 out 与片段着色器里的 in 同名同类型这一约定被破坏——两个阶段之间是靠名字（或显式声明的 location）配对的，名字里多一个空格、类型从 vec3 写成 vec4，链接阶段就会报错。这类错误不会在编译单个着色器时暴露，只有链接才会发现，因此查错时要分清是编译日志还是链接日志。

顶点数组对象

　　顶点数组对象（Vertex Array Object, VAO）可以像顶点缓冲对象那样被绑定，任何随后的顶点属性调用都会储存在这个 VAO 中。

　　这样的好处是，当配置顶点属性指针时，只需要将那些调用执行一次，之后再绘制物体的时候只要绑定相应的 VAO 就行了。这使在不同顶点数据和属性配置之间切换变得非常简单，只需要绑定不同的 VAO 就行。刚刚设置的所有状态都将存储在 VAO 中。

Tip：需要分清 VAO 与 VBO 各存了什么——顶点数据本身仍然在 VBO 里，VAO 记录的是「如何解释这些数据」的配置（属性指针、启用状态、以及关联了哪个 VBO）。所以绘制一个物体时的典型动作是绑定 VAO，而不是重新上传数据；同一个 VBO 也完全可以被多个 VAO 以不同方式解释。

Tip：OpenGL 的核心模式要求使用 VAO，因为它需要借此知道该如何处理顶点输入。如果绑定 VAO 失败，OpenGL 会拒绝绘制任何东西——「代码看起来没问题、画面却一片空白」时，这是首先要排查的一条。

　　一个顶点数组对象会储存以下这些内容：

  • glEnableVertexAttribArray 和 glDisableVertexAttribArray 的调用。
  • 通过 glVertexAttribPointer 设置的顶点属性配置。
  • 通过 glVertexAttribPointer 调用与顶点属性关联的顶点缓冲对象。

小结

　　本节先梳理图形渲染管线的各阶段，再据此写出第一个能画出三角形的完整程序：准备顶点数据、编写并编译两个着色器、链接成程序、说明顶点数据如何解析，最后用绘制调用输出图元。

  • 图形渲染管线：顶点数据依次经过顶点着色器、几何着色器（可选）、图元装配、光栅化（含裁切）、片段着色器，最后由测试与混合写出像素；可编程的是顶点、几何、片段着色器，其余阶段属于固定功能，只能通过状态开关影响。
  • 顶点数据与图元：顶点属性可以承载任意数据，本节只用一个 3D 位置；坐标须落在标准化设备坐标（三轴均在 -1.0～1.0）内，超出部分会被裁掉。绘制调用通过图元常量（GL_TRIANGLES、GL_POINTS、GL_LINE_STRIP 等）声明这些数据该如何被解释。
  • VBO：glGenBuffers 生成对象，glBindBuffer(GL_ARRAY_BUFFER, ...) 绑定目标，glBufferData 一次性把顶点数据复制到显存；第四个参数（GL_STATIC_DRAW 等）只是性能提示，不改变语义。
  • 着色器：用 GLSL 编写，源码先以 C 字符串硬编码，再由 glCreateShader、glShaderSource、glCompileShader 在运行时编译。顶点着色器必须给内置输出 gl_Position（vec4，本节 w = 1.0）赋值；片段着色器必须声明至少一个 out 颜色变量，其名字可自行选取。
  • 着色器程序：glCreateProgram 创建、glAttachShader 附加、glLinkProgram 链接、glUseProgram 激活；链接负责把上一级的输出接到下一级的输入，输入输出不匹配会得到链接错误。链接完成后即可 glDeleteShader 释放两个着色器对象。
  • 链接顶点属性：glVertexAttribPointer(位置, 大小, 类型, 是否标准化, 步长, 偏移) 说明缓冲中的数据布局，配合 glEnableVertexAttribArray 启用属性；其中位置值要与 GLSL 的 layout (location = 0) 对应。
  • VAO：记录属性指针配置、启用状态以及关联的 VBO 与 EBO，核心模式下必须使用，否则 OpenGL 拒绝绘制；配置动作必须发生在绑定 VAO 之后，绘制时只要绑定对应的 VAO。
  • 元素缓冲对象：EBO 以索引描述顶点的组合顺序，配合 glDrawElements 完成索引绘制，使重复顶点只需存储一份——矩形因此从 6 个顶点降为 4 个。EBO 的绑定同样被 VAO 记录，解绑 VAO 之前不要解绑 EBO。
