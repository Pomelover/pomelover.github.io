1.5 纹理

学习笔记系列，教程：Joey de Vries《LearnOpenGL》，中文版地址 learnopengl-cn.github.io。

　　相比用大量顶点去堆砌细节，艺术家和程序员更倾向于使用纹理（Texture）。纹理是一张 2D 图片（也存在 1D 与 3D 的纹理），它可以用来为物体添加细节。可以把它想象成一张绘有砖块的纸：把这张纸无缝地折叠、贴合到 3D 的房子上，房子看起来就有了砖墙的外表。之所以能做到这一点，是因为在一张图片上可以插入非常多的细节，于是物体能够表现得非常精细，而不必为此额外指定顶点。在后面的例子中，之前教程里的那个三角形就会被贴上一张砖墙图片。

Tip：用图片细节替代几何细节，是实时渲染中最划算的一类取舍——顶点数一个不增，外观的信息量却几乎完全由那张图片决定，而且同一张纹理可以复用到成百上千个物体上，显存里只存一份。代价是把复杂度从几何转移到了纹理采样上：GPU 要为每个片段按纹理坐标去查表取值，因此专门配有纹理单元与纹理缓存；本章后面讲的环绕方式、纹理过滤与多级渐远纹理，解决的都是在这次查表上怎样取到不闪烁、不失真的值。

　　为了能够把纹理映射（Map）到三角形上，需要指定三角形的每个顶点各自对应纹理的哪个部分。这样，每个顶点都会关联一个纹理坐标（Texture Coordinate），用来标明该从纹理图像的哪个部分采样（即采集片段颜色）；之后，再在图形的其它片段上进行片段插值（Fragment Interpolation）。

Tip：纹理坐标是归一化的， 代表纹理中心。归一化的直接好处是坐标与纹理分辨率解耦——同一套坐标写好后，换成 512×512 还是 2048×2048 的图片都无需改动，这与 1.4.5 中按顶点位置插值颜色的机制完全一致，只是被插值的量从颜色换成了坐标。另外要留意原点方向：OpenGL 以左下角为原点，而多数图片格式（PNG、JPG）以左上角为原点、 轴向下，二者不一致会让贴图上下颠倒，这也是后面用 stb_image 加载时通常要调用 stbi_set_flip_vertically_on_load(true) 的原因。

1.5.2 纹理过滤

　　纹理坐标不依赖于分辨率（Resolution），它可以是任意的浮点值，因此 OpenGL 需要知道怎样将纹理像素（Texture Pixel，也叫 Texel）映射到纹理坐标上。当一个物体很大、而纹理的分辨率很低时，这件事就变得很重要。由此，OpenGL 也提供了针对纹理过滤（Texture Filtering）的选项。过滤的选项有很多，这里只讨论其中最重要的两种：GL_NEAREST 和 GL_LINEAR。

Tip：纹素（Texel）与屏幕上的像素不是一回事：前者是纹理图像的最小单元，后者是帧缓冲的最小单元。过滤要回答的正是「一个屏幕像素覆盖了多少纹素」——放大时一个纹素被铺到多个像素上，缩小时一个像素要汇总多个纹素，这两种情况的处理方式并不相同，本节后面两张图分别对应它们。也正因为纹理坐标是连续的浮点值，采样点通常落不到纹素正中心，才有「取最近的那个」与「按距离加权平均」这两种取舍。

　　GL_NEAREST（也叫邻近过滤，Nearest Neighbor Filtering）是 OpenGL 默认的纹理过滤方式。当设置为 GL_NEAREST 时，OpenGL 会选择中心点最接近纹理坐标的那个纹理像素。

　　GL_LINEAR（也叫线性过滤，(Bi)linear Filtering）则会基于纹理坐标附近的纹理像素计算出一个插值，近似出这些纹理像素之间的颜色。一个纹理像素的中心距离纹理坐标越近，那么这个纹理像素的颜色对最终的样本颜色的贡献就越大。

Tip：两种方式对应两种「查表」策略：GL_NEAREST 直接取最近的一个纹素，实现简单、开销最低，代价是放大时会出现明显的块状锯齿——像素风游戏刻意保留这种硬边，因此反而会主动选它；GL_LINEAR 把周围纹素按距离加权平均，画面更平滑，代价是要读取并混合多个纹素，开销更高。名字里的 (Bi) 指的是双向：2D 纹理在 、 两个方向上各做一次线性插值，故称双线性（Bilinear）；这个括号也提示了它是线性过滤的一种特例，3D 纹理在三个方向上插值时则称为三线性。

　　当进行放大（Magnify）和缩小（Minify）操作的时候，可以分别设置纹理过滤的选项——例如在纹理被缩小时使用邻近过滤、被放大时使用线性过滤。这同样需要用 glTexParameter* 函数为放大和缩小指定过滤方式，代码看起来会和纹理环绕方式的设置很相似：

Tip：放大与缩小是两个互相独立的参数，取值互不影响，因此「缩小用邻近、放大用线性」这样的组合完全合法。二者要分开设置的原因在于像素与纹素的对应关系不同：放大时一个纹素铺到多个像素上，重点是让边缘显得平滑还是保持硬朗；缩小时一个像素要覆盖多个纹素，若只取其中固定的一个，就会随物体远近不断「跳过」纹素，画面出现闪烁与摩尔纹——这正是下一小节多级渐远纹理要解决的问题。另外，GL_TEXTURE_MIN_FILTER 的初值涉及多级渐远纹理，若把缩小过滤设成带 MIPMAP 的取值却没有生成 mipmap，纹理会被判定为不完整而渲染成黑色，这是初学阶段很常见的一个坑。

多级渐远纹理

　　设想有一个包含着上千物体的大房间，每个物体上都有纹理。有些物体会很远，但它们的纹理却拥有与近处物体同样高的分辨率。由于远处的物体可能只产生很少的片段，OpenGL 从高分辨率纹理中为这些片段获取正确的颜色值就很困难，因为它需要对一个跨过纹理很大部分的片段只拾取一个纹理颜色。在小物体上，这会产生不真实的感觉，更不用说对它们使用高分辨率纹理会浪费内存。

　　OpenGL 使用一种叫做多级渐远纹理（Mipmap）的概念来解决这个问题：简单来说，它就是一系列的纹理图像，后一个纹理图像是前一个的二分之一。多级渐远纹理背后的理念很简单——当距观察者的距离超过一定的阈值时，OpenGL 会使用不同的多级渐远纹理，即最适合物体距离的那一个；由于距离远，解析度不高也不会被用户注意到。同时，多级渐远纹理的另一加分之处是它的性能非常好。下面看一下多级渐远纹理是什么样子的：

Tip：减半会一直进行到 为止，因此一个 的纹理最多有 级。整条 mipmap 链的显存开销并不是原始纹理的若干倍：除了第 0 级之外，其余各级的总面积只相当于原始纹理的 ，即总额外开销约 33%（）。这正是它「省内存」与「省带宽」并存的原因——远处物体读的是小级别纹理，既避免了从大纹理里随机取样造成的抖动，也大幅降低了缓存与显存带宽的压力。

　　OpenGL 有一个 glGenerateMipmap 函数，在创建完一个纹理后调用它，OpenGL 就会承担接下来的所有工作。

Tip：这个函数作用于当前绑定的纹理目标，因此要写在 glBindTexture 之后，而且此时纹理必须已经有数据（即至少上传过第 0 级）——对一张空纹理调用它没有意义。它内部通常用逐级取平均的盒式滤波（Box Filter）生成各级图像，质量一般但对多数用途足够；如果需要更讲究的缩小效果，也可以自己离线生成好、再用 glTexImage2D 的 level 参数逐级上传。生成的级别数由纹理尺寸决定，尺寸减到 时为止，因此这一步必须在尺寸确定之后、绘制之前完成。

　　在渲染中切换多级渐远纹理级别（Level）时，OpenGL 会在两个不同级别的多级渐远纹理层之间产生不真实的生硬边界。就像普通的纹理过滤一样，切换多级渐远纹理级别时也可以在两个不同级别之间使用 NEAREST 和 LINEAR 过滤。为了指定不同多级渐远纹理级别之间的过滤方式，可以使用下面四个选项中的一个来代替原有的过滤方式：

过滤方式 描述
GL_NEAREST_MIPMAP_NEAREST 使用最邻近的多级渐远纹理来匹配像素大小，并使用邻近插值进行纹理采样
GL_LINEAR_MIPMAP_NEAREST 使用最邻近的多级渐远纹理级别，并使用线性插值进行采样
GL_NEAREST_MIPMAP_LINEAR 在两个最匹配像素大小的多级渐远纹理之间进行线性插值，使用邻近插值进行采样
GL_LINEAR_MIPMAP_LINEAR 在两个邻近的多级渐远纹理之间使用线性插值，并使用线性插值进行采样

Tip：这四个选项的命名遵循同一个规则——前一个词描述级别内部（同一张纹理图像里）的过滤方式，后一个词描述级别之间（两张 mipmap 之间）的过滤方式，例如 GL_LINEAR_MIPMAP_LINEAR 就是「级别内线性 + 级别间线性」。所谓「生硬边界」，指的是物体前后移动时 mipmap 级别发生跳变、画面亮度或清晰度突然一跳（popping）；级别之间也采用 LINEAR 时，会同时对两张相邻级别的采样结果做插值，把这一跳抹平。

　　一个常见的错误是把放大过滤的选项设置为多级渐远纹理过滤选项之一。这样做没有任何效果，因为多级渐远纹理主要是使用在纹理被缩小的情况下的：纹理放大不会使用多级渐远纹理，为放大过滤设置多级渐远纹理的选项会产生一个 GL_INVALID_ENUM 错误代码。

Tip：这个错误是静默的——glTexParameteri 本身不返回任何值，它只会把错误码塞进 OpenGL 的错误队列，必须用 glGetError() 主动查询才能发现，而 GL_TEXTURE_MAG_FILTER 会保持原值不变，于是表现为「代码写错了，画面却只是看不出变化」。顺便澄清前面留下的默认值问题：按规范，GL_TEXTURE_MAG_FILTER 的初值是 GL_LINEAR，GL_TEXTURE_MIN_FILTER 的初值是 GL_NEAREST_MIPMAP_LINEAR（缩小过滤的初值本身就带 MIPMAP）；这也说明 1.5.2 中「GL_NEAREST 是默认过滤方式」是一种简化说法——默认值是按放大、缩小两个参数分别定义的，且缩小的初值是 mipmap 系列。

1.5.3 加载与创建纹理

　　使用纹理之前要做的第一件事是把它们加载到应用程序中。纹理图像可能被储存为各种各样的格式，每种都有自己的数据结构和排列，那么怎样才能把这些图像加载进来？一种解决方案是选定需要的文件格式（比如 .PNG），然后自己写一个图像加载器，把图像转化为字节序列。自己写加载器虽然不难，但仍然挺麻烦，而且如果要支持更多文件格式，就不得不为每一种希望支持的格式各写一个加载器。

　　另一种解决方案也许是一种更好的选择：使用一个支持多种流行格式的图像加载库来解决这个问题，比如接下来要用的 stb_image.h 库。

Tip：OpenGL 本身并不认识 .PNG、.JPG 这些文件格式，glTexImage2D 接受的只是一段原始像素数组以及它的格式描述（宽、高、通道数、每通道类型），因此解码工作必须在 CPU 侧完成，这也是需要一个图像加载库的根本原因。实际项目中还常把图片离线烘焙成 GPU 可直接识别的纹理格式（如 DDS、KTX），运行时连解码都省掉，同时还能存放压缩纹理数据。

纹理单元

　　可能会有一个疑问：sampler2D 变量既然是个 uniform，为什么却不用 glUniform 给它赋值？实际上，通过 glUniform1i 可以给纹理采样器分配一个位置值，这样就能够在同一个片段着色器中设置多个纹理。一个纹理的位置值通常称为一个纹理单元（Texture Unit）。纹理的默认纹理单元是 0，它也是默认的激活纹理单元。

Tip：这套机制之所以能「默认就对」，是因为两边恰好都从 0 开始：默认激活的是 GL_TEXTURE0，采样器 uniform 的初值也是 0，于是 glBindTexture 绑上去的纹理自然被采样器取到。一旦用 glActiveTexture 切到别的单元再绑定，采样器就必须同步用 glUniform1i 指过去，否则会采到另一个单元上的纹理（或什么都没绑的单元，表现为黑或白）。另外要记住两点：给采样器赋值前必须先 glUseProgram（与 1.4 中 uniform 的规则一致），而采样器只接受整数单元索引，把纹理 ID 传进去是错的。

　　纹理单元的主要目的是在着色器中可以使用多于一个的纹理。通过把纹理单元赋值给采样器，可以一次绑定多个纹理，只要首先激活对应的纹理单元。与 glBindTexture 类似，可以使用 glActiveTexture 激活纹理单元，传入需要使用的纹理单元：

Tip：这里唯一的坑是顺序：glActiveTexture 只是切换「当前激活的单元」，随后所有 glBindTexture 调用都作用在它上面，因此必须先激活、再绑定；写反了会把纹理绑到上一个仍是激活状态的单元上，表现为「代码看着没错，却采到了别的纹理」。

小结

　　本章从「用纹理替代海量顶点」这一动机出发，依次解决了采样的三件事——坐标怎么定、越界怎么办、放大缩小时怎么取值，最后走通了从图片文件到屏幕上贴图矩形的完整流程。

  • 纹理与纹理坐标：纹理是一张 2D 图片（也有 1D 与 3D），用于在不增加顶点的前提下为物体添加细节；每个顶点关联一组归一化到 的纹理坐标，用坐标获取颜色的过程叫采样（Sampling），其余片段由片段插值补足。注意 OpenGL 以左下角为原点、而图片多以左上角为原点，这正是贴图上下颠倒的根源。
  • 纹理环绕方式：坐标越界时由 GL_TEXTURE_WRAP_S／GL_TEXTURE_WRAP_T 决定取值规则——GL_REPEAT（默认）平铺重复，GL_MIRRORED_REPEAT 镜像平铺，GL_CLAMP_TO_EDGE 把边缘像素向外拉伸，GL_CLAMP_TO_BORDER 在越界处使用 GL_TEXTURE_BORDER_COLOR 指定的边框色（默认透明黑）。
  • 纹理过滤：GL_NEAREST 取中心最接近坐标的那一个纹素，边缘硬、开销低；GL_LINEAR 对附近纹素按距离加权插值，更平滑。放大由 GL_TEXTURE_MAG_FILTER 控制、缩小由 GL_TEXTURE_MIN_FILTER 控制，二者独立；放大只接受这两个取值，传入 MIPMAP 系列会静默产生 GL_INVALID_ENUM。
  • 多级渐远纹理：一系列逐级减半的纹理图像，用于解决远处物体「一个片段跨过大量纹素」造成的失真与闪烁。用 glGenerateMipmap 自动生成；级别内部与级别之间可各自选 NEAREST／LINEAR，共四个缩小过滤选项（GL_LINEAR_MIPMAP_LINEAR 即三线性）。开启带 MIPMAP 的缩小过滤却未生成 mipmap，纹理会不完整而渲染成黑。
  • 加载与创建纹理：用单头文件库 stb_image.h 解码图片——#define STB_IMAGE_IMPLEMENTATION 整个工程只能定义一次；stbi_load 返回像素数组并填出宽、高与通道数；glGenTextures 取 ID、glBindTexture 绑定、glTexImage2D 上传（第三参数为内部格式，带 alpha 的 PNG 须用 GL_RGBA）、glGenerateMipmap 生成 mipmap，最后 stbi_image_free 释放内存。
  • 应用纹理：顶点数据扩充为「位置 + 颜色 + 纹理坐标」共 8 个 float，步长与偏移据此重算；顶点着色器用 layout (location = 2) 接收并转发坐标，片段着色器声明 uniform sampler2D 并用 texture(sampler, coord) 采样，绘制前绑定纹理。
  • 纹理单元：采样器的值不是纹理 ID 而是纹理单元索引；默认激活 GL_TEXTURE0、采样器初值也是 0，故单张纹理无需设置。多纹理时先用 glActiveTexture 激活单元再绑定纹理，并用 glUniform1i 把每个采样器指向各自的单元。
