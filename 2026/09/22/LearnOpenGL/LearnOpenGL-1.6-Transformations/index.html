1.6 变换

学习笔记系列，教程：Joey de Vries《LearnOpenGL》，中文版地址 learnopengl-cn.github.io。

1.6.1 向量

　　向量最基本的定义就是一个方向。或者更正式地说，向量有一个方向（Direction）和大小（Magnitude，也叫做强度或长度）。

Tip：与向量相对的是标量（Scalar）——标量只有一个分量，只表示大小而不带方向，温度、质量、时间都是标量。向量则同时携带两个信息，这一点在后面很容易被忽视：把一个速度向量取反，改变的是方向而不是大小；把它乘以 ，改变的才是大小。也正因为「大小」被单列出来作为一个属性，后面才会有长度与标准化（单位向量）这两小节单独去处理它。

　　由于向量表示的是方向，有些时候很难形象地用位置把它表示出来。为了让这件事更为直观，通常把向量的起点设定在原点 ，再让它指向某个方向、对应到一个点上，这时它就成为位置向量（Position Vector）。起点当然也可以取在其他点，此时可以说：这个向量从该点起始，指向另一个点。

Tip：把「方向」与「位置」两种用法分开看很重要——同一个三元组 既可以读作「朝这个方向走这么远」，也可以读作「空间中这个点」。图形学里多数向量（法线、速度、光照方向）关心的是前者，只有描述顶点坐标时才关心后者；这也是后面齐次坐标用一个 分量区分二者的原因（ 表示位置， 表示方向，方向向量不能被位移）。

向量与标量运算

　　标量（Scalar）只是一个数字，或者说是仅有一个分量的向量。把一个向量与标量相加、相减、相乘或相除时，做法很简单：把向量的每个分量分别与这个标量进行该运算即可。

Tip：严格来说，数学上并没有「向量与标量相加减」这种运算，但多数线性代数库都对它做了支持，例如本教程后面要用的 GLM；用过 NumPy 的话，可以类比它的广播（Broadcasting）机制。要留意运算的方向性：标量在左还是在右，对乘除法没有影响，但颠倒过来的 标量 - 向量、标量 / 向量 是没有定义的，代码里只能写成 向量 - 标量、向量 / 标量。GLSL 与 GLM 都按分量逐个处理这类混合运算，vec3 * float 就是三个分量各乘一次。

向量取反

　　对一个向量取反（Negate）会将其方向逆转。

Tip：取反只翻转方向，不改变大小——长度是各分量平方和的平方根，每个分量变号后平方值不变。实现上就是把向量的每个分量加上负号，等价于用 数乘该向量，因此它同时也是「向量与标量运算」的一个特例。图形学中常用它来求反向的法线、把「从 A 指向 B」换成「从 B 指向 A」，或是在反射公式里把入射方向翻过来。

向量加减

　　向量的加法可以被定义为分量的（Component-wise）相加，也就是把一个向量中的每一个分量加上另一个向量的对应分量。

Tip：几何上这相当于把第二个向量的起点挪到第一个向量的终点，首尾相接后由起点指向终点（即平行四边形法则）；因此两个向量相加要求维度相同，而且它满足交换律——，这一点与后面的矩阵乘法恰好相反。向量减法则是加上第二个向量的相反向量，得到的是两个向量所指向位置之差，在求两点之间的距离或方向时非常有用，这也是本章末尾把位移写进矩阵时的理论依据。

Tip：两种「乘法」的名字里都带乘，但结果的类型完全不同：点乘的结果是一个标量，只剩下大小；叉乘的结果仍是一个向量，携带着方向。符号上也因此区分得很清楚——点乘用点号 ，叉乘用叉号 ，不要写混。这一区别决定了它们各自的用途：需要「一个数」时用点乘（例如求夹角、判断朝向、算光照强度），需要「一个新的方向」时用叉乘（例如由两条边求出平面法线）。

叉乘

　　叉乘只在 3D 空间中有定义，它需要两个不平行向量作为输入，生成一个正交于两个输入向量的第三个向量。如果输入的两个向量本身也是正交的，那么叉乘之后将会产生 3 个互相正交的向量；在接下来的教程中这会非常有用。

Tip：方向由右手定则决定：四指从第一个向量弯向第二个向量，拇指所指即为结果向量的方向，这也意味着叉乘不满足交换律——交换两个输入会得到方向相反的向量，即 。如果两个输入向量平行（或反向平行），叉乘的结果是零向量，此时无法确定唯一的方向。求平面法线、构造一组正交基都依赖叉乘；GLM 中对应 glm::cross(a, b)，GLSL 中对应内建函数 cross(a, b)，与点乘的 dot() 一样都是内建函数。

1.6.2 矩阵

　　向量的内容到此为止，接下来该看看矩阵了。简单来说，矩阵就是一个矩形的数字、符号或表达式数组，矩阵中的每一项叫做矩阵的元素（Element）。矩阵可以用 进行索引， 是行、 是列。

Tip：这种「先行后列」的索引顺序与 2D 图像恰好相反——图像通常写作 ，先列后行，因此描述同一个位置时两者的写法是颠倒的。维度也按同样的顺序记作「行 × 列」，例如 是 2 行 3 列。另外要留意数学上的索引一般从 开始，而代码里从 开始；在 GLM 中这个差异还多一层：glm::mat4 是列主序，m[i] 取出的是第 列，因此下标顺序恰好是「先列后行」，与数学写法相反，访问元素时容易搞混。

矩阵的加减

　　矩阵与标量之间的加减定义为：标量值要加到矩阵的每一个元素上。

　　矩阵与标量的减法也类似。矩阵与矩阵之间的加减，则是两个矩阵对应元素的加减运算，规则与标量运算差不多，只不过只有在相同索引下的元素才能进行运算。也就是说，加法和减法只对同维度的矩阵才有定义：一个 矩阵和一个 矩阵（或一个 矩阵与 矩阵）不能进行加减。

　　同样的法则也适用于减法。

Tip：数学上并没有「矩阵与标量相加减」这样的运算，但很多线性代数库都对它做了支持，例如本教程要用的 GLM；用过 NumPy 的话，可以把它理解为广播（Broadcasting），与前面「向量与标量运算」是同一套东西。要留意矩阵的加减要求维度完全一致，这与后面矩阵乘法「左列数等于右行数」的约束不是一回事： 与 不能相加减，却可以相乘（结果是一个 矩阵），而 与 既不能加减也不能相乘。另外，图形学里真正频繁使用的是 方阵的乘法，加减基本只出现在推导或插值矩阵元素之类的场合。

1.6.4 实践

　　OpenGL 并不自带任何矩阵与向量的知识，这些数学工具要么自己定义一套类和函数，要么交给现成的数学库。本教程选择后者，使用的是专门为 OpenGL 量身定做的数学库 GLM。

GLM

　　GLM 是 OpenGL Mathematics 的缩写，它是一个只有头文件的库，也就是说只需包含对应的头文件就行了，不用链接和编译。

Tip：可以把它理解为「照着 GLSL 的规矩写的一套 C++ 数学库」——类型与函数命名同 GLSL 几乎一一对应（glm::vec3 对 vec3、glm::mat4 对 mat4、glm::radians 对 radians），因此在 C++ 侧算好的数据能自然地传给着色器，不必再做转换。只有头文件的代价是编译期要处理更多的代码，好处是省去了库的构建与链接配置，把 GLM 头文件根目录放进工程的 include 路径即可使用。

Tip：三者的分工可以用一句话概括：glm/glm.hpp 提供核心的向量与矩阵类型（vec3、vec4、mat4）及其基本运算；glm/gtc/matrix_transform.hpp 提供变换矩阵的构造函数 translate、rotate、scale，以及后续投影要用的 perspective、lookAt；glm/gtc/type_ptr.hpp 提供 value_ptr，用来把 GLM 的矩阵数据交给 glUniformMatrix4fv。GLM 的扩展功能大多按 gtc（按需引入）与 gtx（实验性）分组，用到时再单独包含对应头文件即可。

　　下面来旋转和缩放之前教程中的那个箱子：先把箱子在每个轴都缩放到 倍，然后沿 轴旋转 90 度。GLM 希望角度是弧度制的（Radian），所以使用 glm::radians 将角度转化为弧度。注意有纹理的那面矩形是在 平面上的，因此需要把它绕着 轴旋转。由于把这个矩阵传给了 GLM 的每个函数，GLM 会自动将矩阵相乘，返回的结果是一个包括了多个变换的变换矩阵。

Tip：glm::rotate(m, ...) 返回的是 m 左乘新旋转矩阵的结果，因此代码里后写的 scale 处在乘法链的右侧、最先作用于顶点——「先缩放、后旋转」的顺序在代码中表现为「先写 rotate、后写 scale」，与上一节「从右向左读」的规则完全一致。另外要留意 trans 必须已经初始化为单位矩阵（0.9.9 之后的 GLM 中要写成 glm::mat4 trans = glm::mat4(1.0f);），否则函数是在一个零矩阵的基础上相乘，结果恒为零矩阵。

　　第一步是查询 uniform 变量的地址，然后用带 Matrix4fv 后缀的 glUniform 函数把矩阵数据发送给着色器。各参数的含义如下：第一个参数是 uniform 的位置值；第二个参数告诉 OpenGL 将要发送多少个矩阵，这里是 1；第三个参数询问是否希望对矩阵进行转置（Transpose），也就是交换矩阵的行和列。OpenGL 开发者通常使用一种叫做列主序（Column-major Ordering）的内部矩阵布局，而 GLM 的默认布局正是列主序，所以并不需要转置，这里填 GL_FALSE；最后一个参数是真正的矩阵数据，但 GLM 的存储方式并不是 OpenGL 所希望接受的那种，因此要先用 GLM 自带的函数 value_ptr 转换这些数据。

Tip：第三个参数是这一节最容易踩坑的地方——它问的是「要不要由 OpenGL 帮你转置」，而 GLM 与 OpenGL 都采用列主序，双方一致，所以传 GL_FALSE 才是正确的；网上不少示例写成 GL_TRUE，那反而把矩阵转成了错的。只有在矩阵数据是按行主序（row-major）存放时，才需要传 GL_TRUE 让 OpenGL 帮忙换过来。glm::value_ptr 返回的是指向矩阵内部存储的裸指针，类型与 glUniformMatrix4fv 期望的 const GLfloat* 匹配；因为它只是取地址，所以必须在矩阵仍然有效的作用域内调用。另外，glUniformMatrix4fv 作用于当前使用的着色器程序，和 1.4 中其它 glUniform* 一样，调用前要确保已经 ourShader.use()。

小结

　　本章先用向量补齐了变换所需的基础数学（方向与大小、加减、长度与标准化、点乘与叉乘），再引入矩阵，把缩放、旋转、位移三种变换统一写成矩阵乘法的形式，最后用 GLM 把矩阵算出来并通过 uniform 送进顶点着色器——物体的位置与朝向从此只由矩阵决定，顶点数据不再需要改动。

  • 向量：同时携带方向与大小；长度由勾股定理求得，除以长度即得单位向量。点乘的结果是标量（单位向量时为夹角的余弦），叉乘只在 3D 中有定义、结果是正交于两个输入的新向量，两者分别用于”求一个数”和”求一个方向”。
  • 矩阵与矩阵乘法：只有当左侧矩阵的列数等于右侧矩阵的行数时才能相乘，结果矩阵取外层的行列数；矩阵乘法不满足交换律，因此顺序本身就是语义。
  • 变换矩阵：单位矩阵是构造其余变换矩阵的起点。缩放改写对角线元素，位移改写第四列最上面的 3 个值，旋转按旋转轴分别定义； 分量是齐次坐标，它为位移腾出了位置（ 矩阵做不到位移），也是下一章透视投影要用的分量。
  • 矩阵的组合：多个变换可以乘成一个矩阵，书写时位移在左、缩放（旋转）在右，实际作用于向量的顺序要从右向左读，即先缩放、再旋转、最后位移，否则位移量会被缩放、旋转一起改掉。
  • 实践：用 GLM 的 translate、rotate、scale 依次左乘构造变换矩阵，注意 glm::mat4 在 0.9.9 之后默认是零矩阵、必须显式初始化为 glm::mat4(1.0f)；矩阵经由 glUniformMatrix4fv 传给顶点着色器的 uniform mat4，由于 GLM 与 OpenGL 同为列主序，转置参数应填 GL_FALSE。变换矩阵各帧重建，就能让物体随时间旋转、位移。
